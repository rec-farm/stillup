# Reuse across REC products

This migration keeps shared design authority in [`rec-farm/rec-brand`](https://github.com/rec-farm/rec-brand) (formerly `reciam-brand`) and identifies concrete second consumers before introducing a package. The following references were inspected locally on 2026-10-05: Paramtune `bc10cdc`, Handstamp `e7a01d1`, and rec-brand `c13c760` (design version 1.6.0). This change does not modify those repositories.

The shared shape is an HTML document with `data-theme` and `data-product`, built client assets, and a backend that owns URLs and runtime configuration. Handstamp currently uses a TypeScript/Fastify backend, so a Rust crate cannot be its immediate shared implementation. Cross-language fixtures and frontend utilities can serve all three.

## First extraction: theme utility

A future `@rec/theme` package can be framework-independent and contain `ThemeChoice`, strict parsing, resolution against an injected media query, pre-paint script generation, and a controller with `read`, `apply`, `subscribe` and `dispose`. A storage adapter owns reading/writing and cross-tab notifications. Product callers supply their current key and default.

StillUp must retain `stillup-theme` cookie semantics. Paramtune must retain `paramtune-theme` localStorage semantics. Handstamp must retain `reciam-theme`; changing to one global key would change preference ownership and needs a separate product decision. The controller must tolerate unavailable storage, apply the current choice before paint, follow OS changes only in System mode, notify multiple controls, and remove listeners on disposal. React consumers can use `useSyncExternalStore` without the package depending on React.

Before publishing, adopt the utility in StillUp and Paramtune together, verify existing preferences and first-paint behavior, and version its public API. This migration does not create a one-consumer package or claim an extraction has shipped.

## Other extraction boundaries

Use rec-brand's existing generated token pipeline as the starting point for a versioned CSS artifact. Do not establish another token source in StillUp. Token updates should run the brand contrast checks and product visual checks; product-specific monitoring colors and status-page settings remain here.

A small Rust web crate could eventually serve StillUp and Paramtune with escaped document transforms, asset caching and consistent missing-resource responses. It must accept explicit route policy and header configuration. StillUp's public status host and Paramtune's authenticated dashboard redirects are distinct policies; sessions, OIDC, PostgreSQL scheduling, incidents and probe credentials must stay outside that crate. Handstamp can consume equivalent behavior fixtures while retaining its existing shell implementation and CSP script hashes.

Keep documentation data and build-time Shiki integration product-owned until another repository needs the same pipeline. Shared guide-shell components should accept navigation, content and route behavior rather than depend on StillUp's monitoring model.
